# 単一作業の進捗通知キュー

## 確定要件と実装範囲
発話中の音声は完了させ、未再生通知は最新1件へ置換する。今回の対象は明示的に起動した試験セッション内の単一作業のみ。複数作業・タップ・停止復帰・期限・再試行方針は確定していない。

## 実装
- ProgressQueue.psm1: pending / ready / activeを分離。正のSequenceで新旧を判断し、古い順序の到着は最新を上書きしない。同IDは内容ハッシュで照合し、同内容なら重複、異内容ならエラーとする。
- Start-ProgressProbe.ps1: CeVIO合成は独立した子プロセスで実行し、合成中も通知受付を続ける。新しい通知に置換された合成結果は再生しない。再生完了までは次の合成を開始しない。
- AgentAudio.hpp: 受信側と共通のspeech.lockを使用。再生開始前のready取り消しと、native側の指令取得・音声投入を排他制御する。音声再生中は新規通知で停止・差し替えない。
- セッションID・単一ストリーム識別・本文長・ID・Sequenceを検査する。再起動前のセッション宛の配送は拒否する。既存セッションを自動復旧・再送する処理は実装していない。
- nativeの永続claimとセッション内の受信ID台帳は役割が異なる。プロセス再起動をまたぐ本番の台帳・失敗回復は未完了。

Windows起動コマンド:

```powershell
& (Join-Path $env:LOCALAPPDATA 'live2d-agent\Launch-ProgressReceive.cmd')
```

以前の音声試験のモデルウィンドウを閉じて、その受信スクリプトを終了させてから起動する。既存ランナーは動かしたままにする。
CeVIOが空いている場合にFREEを入力。WAITING_FOR_PROGRESSとSessionIdが表示される。この試験中は他作業にCeVIOを使わない。合成終了でワーカープロセスは終了し、CeVIOホストは終了・再起動しない。
スクリプト終了・描画終了・合成失敗時は成功や自動再試行として扱わない。異常終了時の作業記録やWAVはWindowsに残る。これは本番の保存・再開ポリシーを確定するものではない。

## 非公開配送
live2d-agent-notifications側に、単発の進捗データ配送workflowとA/B/Cの音声受入試験workflowを配置。
進捗配送はcommitで固定した通知を認証付きで取得し、セッションIDを照合して、Windowsに識別付きの不変ファイルとして配置する。配送ジョブは発話完了を待たず終了するため、A発話中に次の配送が可能。任意シェル実行へ通知本文を接続しない。
Gitの同名ファイルは送信元の入口であり、Windows側で同じcurrent.jsonを上書きして完了扱いする構成ではない。各pushのcommit、通知ID、Sequence、セッションの照合を行う。
実進捗本文を公開コード側へ置かない。Codexの実行形態・イベント連携は引き続き別途未検証。

## Windows検証結果（2026-09-10）
nativeビルドrun 34469574026成功。
非公開側のsetup run 34469921787 / job 102847170823成功。

状態管理試験:
- A active中にB→C: Aを保持し、pendingはCのみ。
- A再送: pendingを変えず重複判定。
- 古い合成結果: readyへ移さない。
- 未取得のready: 新通知で取り消し可能。
- 同ID異内容、別セッション、対応しない完了: エラー。
- 逆順到着: 新しい通知を上書きしない。

native統合試験:
- 無音WAVでAのplayback_submittedを確認後、B/CとAの重複を受信。
- 完了順A→C。Bのnative claimなし。Aの重複抑止。
- 自分で起動した試験ウィンドウを通常終了、終了コード0。
- CeVIOAccessed=false。これは実声での聴取・口パク品質の目視合格ではない。

初期の状態試験で別セッション拒否の回帰試験が失敗。PowerShellの-and/-orを混在させたSequence型検査の括弧不足を入力検査の所有処理で修正し、同じ試験で成功を確認した。検査の削除・合格条件緩和はしていない。

## 残る受入確認
ささら音声でAを最後まで読み、Bを読まずCを読むこと。通知ごとの受付・合成・再生時刻と実際の発話開始の観測。合成中の置換を実音声で試すこと。口閉じ・最前面・画面品質・他アプリへのCeVIO譲渡。Codex個別送信。
今回のキューは単一の生存セッション用であり、常用アプリ完成・全要件合格とは扱わない。
