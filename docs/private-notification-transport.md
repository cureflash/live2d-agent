# 非公開通知配送への移行

## 確定事項
ユーザーは、実際の作業進捗本文を扱う通知用の非公開リポジトリを別に用意する構成を承認した。公開の live2d-agent はコード・仕様・非私的な固定試験データ用とし、実進捗本文を追加しない。
作成名は live2d-agent-notifications を提示する。作成・Private属性・このチャットからのアクセスはいずれもまだ未確認。

## 接続の準備
このセッションのGitHubツールにはファイル作成・更新機能があるが、リポジトリを新規作成する機能がない。ユーザーがGitHubの作成画面でOwner=cureflash、名前=live2d-agent-notifications、Private、READMEありとして作成する。
その後、リポジトリの非公開属性とコネクターからの読み書きを確認してから配送コードを配置する。アクセスできない場合、実進捗を公開リポジトリへ戻すことはしない。

## Windows接続の未確定事項
既存のリポジトリ単位ランナーは live2d-agent に登録されている。別リポジトリのジョブも受けられるとは扱わない。
第一候補は通知用リポジトリに別の配送ランナーを登録し、そのリポジトリ内のジョブトークンで通知データを取得する構成。登録・認証変更は具体的な手順を準備した後にユーザー確認して行う。既存ランナーの登録やmakemovie設定を勝手に変更しない。
描画・合成のプロセスはユーザーの対話セッションで起動し、配送ジョブの寿命と切り離す。配送ジョブは受信口へデータを渡すだけとする。
本文は公開ログ・Artifacts・公開コードへ転記しない。非公開Gitでもコミットした本文は履歴に残るため、本文の削除・履歴保持方針は別途未確定。

## 次の検証
非公開属性とアクセスを確認後、固定文で新経路の単発受信を試す。その後、単一作業のA発話中にB、Cを送り、Aを完了してBを破棄しCを読む動作と重複抑止を検証する。
複数作業、停止・復帰、期限、再試行、タップ競合の未確定事項をこの構成選択で確定したものとは扱わない。Codex実行形態と個別接続検証も未完了。

## 検証済み事項の追記
直前のWeb Work→GitHub→Windows単発試験で、ユーザーは聴取に続いて「声に合わせて口も動いた」と確認した。この1件の同期の目視確認として扱い、連続通知・他の送信元・動作品質全項目の合格へ拡張しない。
